# Test session, 18 November 2026

This was a paid run of cluster `grow-room-poc` in `us-west-2`. I brought it up, ran `verify`, installed Kyverno, checked the image policy in Audit and then in Enforce, and tore it down. Times on this page are America/Denver. November 2026 is MST (UTC-7). The window was about 12:08 PM to 12:29 PM MST.

Commands are PowerShell from `C:\src\grow-room-platform`. Profile `GrowRoom`. The cluster region is `us-west-2`.

Kyverno is the admission policy in the cluster. A PolicyReport is Kyverno's record of whether a resource passed a rule. Enforce means a failed check is rejected. Audit means the same check is only written down.

## What the checks showed

`up` then `verify` is the same pair as the [3 November test session](2026-11-03.md). `verify` ended `ALL CHECKS PASSED`.

The first `verify` failed `POST /audit/batches` because Windows still had a stale DNS answer for `app.mygrowroom.click`. The name had just been created. `Clear-DnsClientCache` cleared the client cache, and the next `verify` passed.

Kyverno is not part of `up`. I installed it with Helm while the cluster was up:

```powershell
helm repo add kyverno https://kyverno.github.io/kyverno/
```

```powershell
helm upgrade --install kyverno kyverno/kyverno -n kyverno --create-namespace --version 3.9.2 --wait
```

Chart 3.9.2 is Kyverno v1.19.2. Chart 3.10.0 is Kyverno v1.20.0. In v1.20.0, `ClusterPolicy` `verifyImages` is slated for removal. This policy is still a `ClusterPolicy`, so the install stays on 3.9.2. Moving the rule to `ImageValidatingPolicy` is a later task. The same note is in the policy file and on [Phase 5](../phases/phase-5-supply-chain.md).

In Audit, `kubectl get policyreport -n grow-room` showed `pass=1` and `fail=0` for all 3 sensor-service pods, the ReplicaSets, and the Deployment. The image was `ghcr.io/tontoblanco/grow-room-platform:sha-c8985e5`. `ci.yml` signed that image with cosign 2.6.5 and the legacy `.sig` tag (`sha256-<digest>.sig`).

I then set `failureAction: Enforce`, `mutateDigest: true`, and `verifyDigest: true`, and applied the file. Three checks followed.

1. A rollout restart of sensor-service admitted the signed image. Kyverno rewrote the pod image to the digest, which pins what runs if the tag moves later. The pods were `ghcr.io/tontoblanco/grow-room-platform:sha-c8985e5@sha256:2393330813cde2b85a3af42a35e69910741ae4a2325deefdab2f20c1f0871c58`.
2. A server dry-run asks the API server to admit the pod and then discards it. A dry-run pod in namespace `grow-room` with image `ghcr.io/tontoblanco/grow-room-platform:sha-8b294a9` was denied. The message was `signed-by-ci-on-main: failed to verify image ...sha-8b294a9: .attestors[0].entries[0].keyless: no signatures found`. That image's cosign 3 referrer signature is invisible to Kyverno. Kyverno 1.19 looks up the legacy tag `sha256-<digest>.sig`. Cosign 3 wrote an OCI referrer, which is the same gap as the [3 November](2026-11-03.md) `no signatures found` result.
3. A pod with `busybox:1.36` was admitted. The policy matches `ghcr.io/tontoblanco/grow-room-platform*` in namespace `grow-room`. `busybox` is outside that match, so Enforce does not look at it.

`/healthz` stayed ok through this.

`down` destroyed 154 resources. The leftover sweep was 0. Windows PowerShell 5.1 printed `terraform destroy reported no exit code`. That warning is the empty `ExitCode` on the `Start-Process` object after `WaitForExit`. The sweep ran anyway. The same warning is on the [7 November test session](2026-11-07.md).

## Lessons

The Windows DNS client cache can make the first `verify` miss `app.mygrowroom.click` after `up` creates the record. `Clear-DnsClientCache` is the command that cleared it. The name is real. The cached answer was stale.

The Helm chart version is part of the result. `helm upgrade --install` without `--version` follows whatever the repo currently calls newest. Chart 3.10.0 would install Kyverno v1.20.0 and put this `verifyImages` rule on a release that plans to remove it. The pin is `--version 3.9.2`.

## Session order

This is the order for this day. The planning figure in the runbook is about 0.70 USD per hour while the stack is up. That is an estimate, not a Cost Explorer total. Tear down the same day.

1. Run `.\scripts\aws-poc.ps1 up` and type `yes` only when the bill should start.
2. Run `.\scripts\aws-poc.ps1 verify`. If `POST /audit/batches` cannot resolve `app.mygrowroom.click`, run `Clear-DnsClientCache` and run `verify` again. A pass ends with `ALL CHECKS PASSED`.
3. Install Kyverno chart 3.9.2 with the command above. On this day I applied `k8s/aws-poc/kyverno-verify-images.yaml` in Audit first. Those reports were `pass=1` `fail=0`.
4. Set `failureAction: Enforce`, `mutateDigest: true`, and `verifyDigest: true` in the same change, and apply the file again. That is the file in Git after this session.
5. Roll the signed image and confirm Kyverno pinned the digest. A dry-run of an in-scope image Kyverno cannot verify should be denied. An image outside the match, such as `busybox:1.36`, is still admitted.
6. Confirm `/healthz` is ok.
7. Run `.\scripts\aws-poc.ps1 down`. On Windows PowerShell 5.1, `terraform destroy reported no exit code` is a warning, and the leftover sweep still runs.

The 18 November session followed this shape. Verify ended `ALL CHECKS PASSED` after the DNS cache clear. Audit passed. Enforce admitted `sha-c8985e5` and denied `sha-8b294a9`. Teardown destroyed 154 resources, and the leftover sweep was 0.
